01

比對原理

AOI 和 CP 是兩套完全獨立的系統，各自用自己的座標系統記錄同一片 wafer。 報表要做的事，就是把兩套座標「對上」，再逐顆比對結果。整體分成四個步驟：

解析 AOI 標記檔

讀取每片 wafer 的 RowData 網格，把不是 ___（wafer 外）、不是 000（正常）的座標記為一筆「AOI 標記」，並記下它的 code 值與 (X, Y) 位置。

解析 CP 測試檔

讀取 Serial#,Site#,Bin#,SBin#,XAdr,YAdr 資料表，建立一張「座標 → Bin 值」的對照表（dieMap）。Bin=1 視為 Pass，其餘視為 Fail。

座標換算

因為兩套系統的原點、掃描方向不一定相同，AOI 的座標要先套用「軸反向」設定，再加上 X/Y 位移量，才能換算成 CP 座標：CP_XAdr = AOI_X ± Xoff、CP_YAdr = AOI_Y ± Yoff。

逐點比對、分類

用換算出的座標去查 CP 的 dieMap：查不到 → 未匹配；查到且 Bin=1（Pass）→ Overkill Suspected；查到且 Bin≠1（Fail）→ Confirmed 真缺陷。

wafer 怎麼配對到同一批（Lot）

每片 AOI 檔用檔案內容裡的 WAFER: 欄位當 key，每片 CP 檔用內容裡的 Wafer ID 欄位當 key， 兩邊字串必須完全相同才會配對成功（例如都要是 RP69778-01）。 報表比對的是檔案內容裡寫的 ID，不是壓縮檔或檔名本身——這點是後面「疑難排解」最常見的誤解來源。

02

兩邊分別讀什麼欄位

上傳的每個 .csv，報表只認特定的標頭與欄位，其餘內容會被忽略。

AOI 標記檔

每片 wafer 一個 .csv，例：RP69778-01.csv
LOT:RP69778
WAFER:RP69778-01
ROWCT:26
COLCT:28
RowData:___ ___ 000 000 ...
RowData:___ 000 000 X01 ...

CP 測試檔

每片 wafer 一個 .csv，例：RP69778-01…dlogTDO.csv
Lot ID    : RP69778
Wafer ID  : RP69778-01
Serial#,Site#,Bin#,SBin#,XAdr,YAdr
0,5,1,1,13,8
1,6,1,1,14,8

兩邊都支援 .zip（內含各片 wafer 的 .csv，可含子資料夾）或個別 .csv，同一批可分多次上傳，系統會依 Wafer ID 自動彙整。

03

Wafer Map 三色怎麼看

「所有 WAFER MAP 總覽」裡，每片 wafer 的每一顆 AOI 標記 die 會依比對結果著色：

黃 · Overkill Suspected

AOI Fail，但 CP 該座標是 Pass（Bin=1）。代表 AOI 很可能誤判，這顆 die 電性其實正常。

紅 · Confirmed

AOI Fail，CP 該座標也是 Fail（含查不到座標的「未匹配」）。代表 AOI 標記的很可能是真缺陷。

綠 · 其餘 die

wafer 上沒被 AOI 標記異常的其他 die，僅作為底圖參考，不計入統計。

上方彙總表中的 Overkill Suspected 率 = 黃色顆數 ÷（黃色＋紅色）顆數，用來評估這批 AOI 設定的誤殺比例。

04

操作步驟

實際操作時，畫面由上到下依序對應以下步驟：

上傳 AOI 與 CP 檔案Step 1

左邊丟 AOI 的 .zip 或 .csv，右邊丟 CP 的 .zip 或 .csv。可以分批、分次上傳同一批 Lot 的不同 wafer，系統會累積在清單裡。

展開「進階座標校正設定」選填

預設 Xoff=6、Yoff=7，若比對後「未匹配」數量偏高，回來調整位移量或勾選 X／Y 軸反向，重新分析。

點「分析並產生報表」

系統會依 Wafer ID 把 AOI 與 CP 逐片配對、套用座標換算、計算三色分類，並依 Lot 分組顯示。

閱讀彙總表格與總覽 Wafer Map

每個 Lot 區塊上方是總 AOI 標記數 / Overkill / Confirmed 統計，下方表格列出每片 wafer 的細節；再往下是所有 wafer 的縮圖總覽，方便一次掃過整批。

「匯出彙總 CSV」選填

把目前的比對結果（含每片 wafer 的統計與 Confirmed die 座標）匯出成 CSV，方便存檔或帶去別的系統。

05

附加功能：AOI 影像 ↔ Wafer Map 位置對應

主報表只看數字座標；如果要回頭確認「某顆標記 die 的 AOI 影像長什麼樣子」，可以用頁面下方這個獨立功能：

上傳完整的 AOI zip（每片 wafer 子資料夾內同時有 .csv 網格檔與多張 X_Y_Z.jpg 影像）。 系統會從檔名解析出 X、Y（座標）與 Z（同一顆 die 上第幾筆缺陷紀錄），自動把每張影像標註回 wafer 網格圖上對應的位置。

在主報表的總覽圖點某片 wafer 的編號，會自動捲動並跳到這裡對應的影像位置圖；同一座標有多張影像時，圖上僅顯示一個 Z 值，其餘可在對照表或匯出的 xlsx 中查看。

06

疑難排解

幾個常見狀況與排查方向：

⚠ 「找不到對應 CP 檔的 wafer」— 整批都對不上

先確認 AOI 與 CP 檔案內容裡的 Lot／Wafer ID 是否逐字相同——報表比的是檔案內容，不是檔名或壓縮檔名。實際案例：

AOI 內容　WAFER: RP69778-01 CP 內容　Wafer ID: RP69678-01 ← 第4碼不同，比對永遠失敗

這通常是某一邊系統的操作員在登錄 Lot 號碼時打錯（多半是 CP 測試站台的 ATE 系統人工輸入），不是報表程式的 bug。 排查方式：跟 MES／測試站台日誌核對正確 Lot 號碼，確認同一批後，把打錯那邊的 Lot ID／Wafer ID 欄位改正再重新匯入。

⚠ 「未匹配」數量偏高

Wafer 有配對成功，但很多 AOI 標記換算後的座標在 CP 資料裡查不到，代表座標系統沒對齊。

回到「進階座標校正設定」，嘗試調整 Xoff / Yoff，或勾選 X／Y 軸反向後重新分析，觀察未匹配數量是否下降。

⚠ zip 上傳後沒有任何檔案出現

確認 zip 裡是 .csv（而非 .kla、.klaExt 等其他格式），且檔案未被額外壓縮成巢狀 zip；macOS 打包產生的 __MACOSX 目錄會自動被忽略，不影響解析。
